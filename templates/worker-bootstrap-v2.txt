STEPS

  1. Confirm `pwd` is `assigned_worktree` (cd into it only if it is not).
  2. Start the run, before any other work:
       {{orc_bin}} run-start --run-id=<run_id> --agent-id={{agent_id}}
  3. Explore: signal the phase, then read the task markdown at `task_spec_path`:
       {{orc_bin}} progress --event=phase_started --phase=explore --run-id=<run_id> --agent-id={{agent_id}}
     Explore is read-only: send the implement phase signal before editing any file or running `npm test`.
     Load past discoveries for this domain (non-fatal; a sandboxed worker may not reach the memory store):
       WING=$(echo "<task_ref>" | cut -d'/' -f1)
       {{orc_bin}} memory-wake-up --wing="$WING" 2>/dev/null || true
       {{orc_bin}} memory-search "<query>" --wing="$WING" 2>/dev/null || true   # targeted lookup in an unfamiliar area
  4. Implement in the assigned worktree:
       {{orc_bin}} progress --event=phase_started --phase=implement --run-id=<run_id> --agent-id={{agent_id}}
     Gate: `npm test` MUST exit 0 before the review phase.
     Optionally record a significant pattern, error or decision for future sessions:
       {{orc_bin}} memory-record --content="<description>" --wing="$WING" --hall=<errors|decisions|patterns|observations> --room=<topic>
  5. Signal review and commit:
       {{orc_bin}} progress --event=phase_started --phase=review --run-id=<run_id> --agent-id={{agent_id}}
       git commit -m "feat(<scope>): <outcome>"   # or fix(<scope>) / chore(<scope>); never --no-verify

WHEN BLOCKED

Tool permission prompts resolve through your local permission handling; never raise run-input-request for them.
Raise one (preferred over run-fail) only for ambiguous or missing spec requirements, merge conflicts you cannot resolve without a human, an unavailable external dependency (service down, credential missing), or a new npm dependency you need approved:
  {{orc_bin}} run-input-request --run-id=<run_id> --agent-id={{agent_id}} --question="Blocked on <specific situation>. <What you need from master>."
It notifies the master and waits for the matching input_response while keeping the run active.
If the task cannot be completed even with master input (--policy defaults to requeue; block prevents retry):
  {{orc_bin}} run-fail --run-id=<run_id> --agent-id={{agent_id}} --reason="<explanation>" [--policy=requeue|block]

RULES

- Lease renewal is automatic via phase signals (and, in Claude sessions, your tool calls); outside Claude, keep sending phase signals as you move through the phases.
- Staying active is not progressing: with no phase change, commit or lifecycle event for a long stretch (60 min by default) the coordinator flags the run to the master. If stuck, call run-input-request rather than cycling tool calls.
- Do not end your turn while the run is unfinished: call run-work-complete, run-input-request or run-fail first. In Claude sessions a premature stop is blocked with a reason; act on that reason.
- Keep a to-do list for the run (TaskCreate/TaskUpdate or TodoWrite, whichever this session offers): one item per meaningful step, each with a present-tense activeForm (e.g. "Fixing findings from the critic"), exactly one in_progress. The operator sees that label in orc watch.
- When you start a long step with no to-do item, say what you are doing: {{orc_bin}} progress --event=heartbeat --run-id=<run_id> --agent-id={{agent_id}} --note="<short text>"
- Do not merge to main, delete the worktree or delete the branch; the coordinator does.
